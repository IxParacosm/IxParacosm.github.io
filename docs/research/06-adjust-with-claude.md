# 6. The "Adjust this process" button

_Research topic: "Adjust this page" / "ask Claude" affordance for process pages in the HQ admin app: GitHub Action, claude.ai/code deep links + Routines, Messages API via Cloudflare Worker, remote MCP server, Agent SDK_

## Summary

Recommended design for a solo operator maintaining a static, no-build-step site with Claude Code:

PRIMARY ("Adjust this page"): the button builds a prefilled Claude Code on the web URL and opens it in a new tab: `https://claude.ai/code?prompt=<urlencoded brief>&repositories=IxParacosm/IxParacosm.github.io&environment=Default`. Zero backend, zero secrets in the page, runs on the operator's claude.ai subscription, the operator reviews/edits the prompt before pressing Enter, and the session pushes a `claude/...` branch from which the operator clicks "Create PR". Merging the PR to the Pages branch is the deploy. The page captures: `page_id` (e.g. `kits.create`), the git SHA baked into the page at publish time, the page's own config object (e.g. the kit-type schema JSON the page renders from), the implementing file paths (e.g. `site/pages/kits.html`, `site/data/kit-types.json`), the operator's free-text request, and standing constraints ("static site, no build step, keep sample data, update CHANGELOG"). Prompts are URL-encoded; for long briefs the page writes a gist/raw file and passes `prompt_url=` instead (must be CORS-readable). Fallback for the same button: a GitHub `/issues/new?title=&body=&labels=claude` link; with the Claude GitHub App + `anthropics/claude-code-action@v1` installed and `@claude` in the issue body, Claude opens the PR unattended.

SECONDARY (fire-and-forget, optional later): a Routine with an API trigger. The page never holds the token; a tiny Cloudflare Worker (behind Cloudflare Access) POSTs to `https://api.anthropic.com/v1/claude_code/routines/{trig_...}/fire` with `{"text": <brief>}`; the routine's saved prompt must explicitly say to act on the `<routine-fire-payload>` block. Returns a session URL to show the operator. Limits: 30 fires/hour/routine, 100/hour/account, no idempotency, research preview.

"JUST ASK A QUESTION" mode: a Cloudflare Worker proxy (`/api/ask`) that calls `POST /v1/messages` with `stream: true` using `@anthropic-ai/sdk` (Workers are a supported runtime), model `claude-opus-5-5` ($4/$20 per MTok, cache reads $0.20/MTok, 512-token cache minimum) with `output_config.effort: "low"` for chat, the kits/accounts JSON placed first in the system prompt under `cache_control: {type:"ephemeral"}`, and the SSE `text_delta` events relayed to the page. Optionally give the Worker read-only tools (`find_kit`, `list_accounts`) or point it at the same remote MCP server via the `mcp_servers` + `mcp_toolset` beta. Never ship the API key to the browser: the SDK's `dangerouslyAllowBrowser` sends `anthropic-dangerous-direct-browser-access: true`, which only exists so the API accepts CORS calls from pages that have already exposed the key.

TERMINAL ACCESS: a stateless remote MCP server on Cloudflare Workers from the `cloudflare/ai/demos/remote-mcp-authless` template (`createMcpHandler` from `agents/mcp/server`, served at `/mcp`), exposing `list_kits`, `get_kit`, `list_accounts`, `upsert_kit` over the same D1/KV/JSON the site reads; added to Claude Code with `claude mcp add --transport http hq https://hq-mcp.<acct>.workers.dev/mcp --header "Authorization: Bearer ..."` or committed as `.mcp.json`. The Agent SDK is not needed: it is a Node/Python library that runs the Claude Code binary (not Workers-compatible) and requires an API key, which duplicates what Claude Code + the MCP server already give the operator.

## Facts

- **verified** Claude Code on the web accepts URL query parameters to prefill a new session: `prompt` (alias `q`), `prompt_url` (URL to fetch the prompt from, 'for prompts too long to embed in a query string', must allow cross-origin requests, ignored when `prompt` is set), `repositories` (comma-separated owner/repo, alias `repo`), `environment` (name or ID). Values must be URL-encoded. Example: `https://claude.ai/code?prompt=Fix%20the%20login%20bug&repositories=acme/webapp`. The doc frames this as 'a button in your issue tracker that opens Claude Code with the issue description as the prompt'. ([source](https://code.claude.com/docs/en/web-quickstart#pre-fill-sessions))
- **verified** Cloud sessions: each task gets its own session and branch; when Claude reaches a stopping point it pushes the branch; the operator selects 'Create PR' in the diff view (full PR, draft, or GitHub compose page). Cloud sessions require Pro, Max, or Team plans (Enterprise with premium seats). Permission modes available in the cloud are Auto, Accept edits, Plan. ([source](https://code.claude.com/docs/en/web-quickstart))
- **verified** Cloud sessions can clone any public repository, but a private repository only when the Claude GitHub App is installed on it (or GitHub was connected via `/web-setup` with a gh token). Installing the app also enables Auto-fix for PRs (Claude reacts to CI failures and review comments). ([source](https://code.claude.com/docs/en/claude-code-on-the-web#github-authentication-options))
- **verified** From a terminal, `claude --cloud "task"` creates a new cloud session for the current repo's GitHub remote; `claude -p "message" --cloud <session-id>` queues a follow-up into an existing session and exits; `--output-format json` returns `{ok, session_id, url}`. ([source](https://code.claude.com/docs/en/claude-code-on-the-web#from-terminal-to-cloud))
- **verified** The terminal deep link scheme is `claude-cli://open?repo=owner/name&q=<urlencoded prompt>` (also `cwd=`); `q` max 5,000 characters; prompt is prefilled but not sent; GitHub-rendered Markdown strips `claude-cli://` links (put them in a code block). Desktop scheme: `claude://code/new?q=<text>&folder=<path>` (`prompt` is an alias for `q`); desktop chat `claude://claude.ai/new?q=` truncates at roughly 14,000 characters. ([source](https://code.claude.com/docs/en/deep-links))
- **verified** Routines (research preview; Pro, Max, Team, Enterprise) are saved prompt + repos + connectors configs run as cloud sessions with Schedule, API, and GitHub-event triggers. The API trigger is added from the web UI only; the per-routine bearer token (`sk-ant-oat01-...`) is shown once; regenerating revokes the previous token. Claude pushes work to `claude/`-prefixed branches. The routine prompt must explicitly opt in to acting on fire text, e.g. 'Investigate the alert described in the routine-fire-payload block', otherwise the text is inert context. ([source](https://code.claude.com/docs/en/routines))
- **verified** Routine fire endpoint: `POST https://api.anthropic.com/v1/claude_code/routines/{routine_id}/fire` (id is `trig_`-prefixed) with headers `Authorization: Bearer <token>`, `anthropic-version: 2023-06-01`, optional JSON body `{"text": "..."}` (max 65,536 chars, freeform, not parsed). 200 returns `{type:"routine_fire", claude_code_session_id, claude_code_session_url}`. Errors: 400 (paused routine / text too long), 401, 403, 404, 429 (`Retry-After`), 503. No idempotency key: retries create multiple sessions. Not in SDKs; billed to the claude.ai subscription, not the API. ([source](https://platform.claude.com/docs/en/api/claude-code/routines-fire))
- **verified** Routine rate limits: 30 per hour per routine (shared across API fires, Run now, and one-shot re-arms); 100 API fires per hour per account; 100 scheduled runs per hour per account; no overage. Minimum schedule interval is one hour. ([source](https://code.claude.com/docs/en/routines#usage-and-limits))

## Recommendations

- Build the 'Adjust this page' button as a client-side link builder (no backend): assemble a brief from {page_id, site git SHA, the page's config JSON, implementing file paths, operator's request, standing constraints} and open `https://claude.ai/code?prompt=<encodeURIComponent(brief)>&repositories=<owner/repo>&environment=Default` in a new tab. Keep the encoded prompt under ~4,000 chars; above that, upload the brief to a CORS-readable location (e.g. a Worker route or raw file the page writes) and use `prompt_url=` instead.
- Standardize the brief template so Claude Code gets the same shape every time: `## Page` (id, route, file paths), `## Current config` (fenced JSON), `## Request` (operator text), `## Rules` (static site, no build step, update sample data + CHANGELOG, open a PR, do not touch other pages). Keep the authoritative per-page config in a committed JSON file (e.g. `site/data/pages/kits.create.json`) so 'adjust' usually means editing a data file rather than code.
- Deploy path: Claude Code pushes a `claude/...` branch -> operator clicks Create PR in the session -> merge to the Pages/Cloudflare Pages branch triggers the deploy. Add a `CLAUDE.md` at the repo root describing the page registry, data files, and the no-build rule so every session (web, Action, Routine) follows the same conventions.
- Fallback/unattended variant of the same button: a GitHub `/issues/new?title=<page_id: request>&body=<brief>&labels=claude` link. Install the Claude GitHub App and `anthropics/claude-code-action@v1` with `on: issues: types:[opened]` + `issue_comment` and `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}` (subscription) or `anthropic_api_key`; include `@claude` in the issue body so it opens the PR without a session. Only the operator (write access) can trigger it, which is the right default; do not set `allowed_non_write_users`.
- Implement 'just ask a question' as a Cloudflare Worker route `/api/ask` (behind Cloudflare Access or a shared secret) using `@anthropic-ai/sdk` with `client.messages.stream(...)`, `model: 'claude-opus-5-5'`, `output_config: {effort: 'low'}`, a frozen system prompt that embeds the kits/accounts JSON first with `cache_control: {type:'ephemeral'}` (>=512 tokens), and relay `text_delta` events as SSE to the page. Add `fallbacks: 'default'` with beta `server-side-fallback-2026-07-01`, and check `stop_reason === 'refusal'`. Optionally switch to `claude-sonnet-5-5` for a cheaper tier, but do not use Haiku 4.5 for this unless the cached context exceeds 4,096 tokens.
- Expose the kits data to Claude Code in the terminal with a remote MCP server on Workers from the `cloudflare/ai/demos/remote-mcp-authless` template: tools `list_kits`, `get_kit(kit_id)`, `list_accounts(filter)`, `upsert_kit`, `assign_kit_to_va`; protect it with a bearer header checked in the Worker; commit `.mcp.json` with `${HQ_MCP_TOKEN}` expansion. Reuse the same server from the Q&A Worker via `mcp_servers` + `mcp_toolset` (beta `mcp-client-2025-11-20`) so there is one tool surface.
- Treat Routines as phase 2: create a 'HQ page adjust' routine whose saved prompt says 'Implement the change request in the routine-fire-payload block on the HQ repo and open a PR', add an API trigger, store the `trig_` URL + token as Worker secrets, and have `/api/adjust` POST `{text: brief}` and return `claude_code_session_url`. Use it only for fire-and-forget requests; keep the claude.ai/code link as the reviewed path.
- Skip the Claude Agent SDK for this project: it needs a long-running Node/Python process with an API key, cannot run in a Worker, and offers nothing over Claude Code + a remote MCP server for a solo operator. Revisit only if you later want a self-hosted 'workflow editor' agent with custom permission callbacks.

## Gotchas

- `claude.ai/code?prompt=` prefills the composer; nothing runs until the operator presses Enter and the repo must already be reachable (public, or Claude GitHub App installed / `/web-setup` done). Private repos silently fail to appear otherwise.
- `prompt_url` requires a CORS-enabled URL; a raw GitHub file works for public repos, but a private Pages/Worker route must send `Access-Control-Allow-Origin` for claude.ai.
- GitHub strips `claude-cli://` and `claude://` links in issues/READMEs (renders plain text) - only use https links on GitHub-rendered pages.
- GitHub `/issues/new` returns `414 URI Too Long` above an undocumented limit (community: ~2-8 KB). Keep the issue body short and link to a committed brief file for context.
- claude-code-action only fires when the triggering user has write access and is not a bot; `@claude` must be a whole word. A workflow in a GitHub Pages repo also spends Actions minutes per run; set `--max-turns` and a job `timeout-minutes`.
- Routine fire payloads arrive wrapped as untrusted `<routine-fire-payload>`; if the routine's saved prompt does not reference it, the change request is ignored. The `/fire` endpoint has no idempotency (retries create duplicate sessions), is a research preview, and the token is shown once.
- Routines, cloud sessions and `/schedule` require a claude.ai subscription login (Pro/Max/Team); they do not work with an API key or Bedrock/Vertex configs, and cannot be offered to VAs through a product per the Agent SDK terms.
- Never put `ANTHROPIC_API_KEY` in the static site. `dangerouslyAllowBrowser` + `anthropic-dangerous-direct-browser-access: true` exists only for trusted internal/dev use; anyone who can load the page can copy the key.
- Prompt-cache minimums differ by model: 512 tokens on Opus 5.5/Sonnet 5.5 but 4,096 on Haiku 4.5; a small kits JSON on Haiku silently never caches. Any byte change before the breakpoint (timestamps, unsorted JSON) also invalidates the cache - verify with `usage.cache_read_input_tokens`.
- Opus 5.5: thinking cannot be disabled and default effort is `medium`; set `output_config.effort: 'low'` explicitly for chat, and do not send `tool_choice: any/tool` (400).
- The MCP connector needs a publicly reachable HTTP MCP server (no STDIO) and is not available on Bedrock/Vertex; it also requires both `mcp_servers` and a matching `mcp_toolset` entry or the request is rejected.
- Cloudflare docs were unreadable from this session; the template was verified from the cloudflare/ai GitHub source. Older write-ups describe `McpAgent` + `/sse` + Durable Objects; the current template is stateless `createMcpHandler` at `/mcp` and Claude Code's SSE transport is deprecated - use `--transport http`.
- Cloud sessions and Routines run on Anthropic infrastructure with a Trusted network allowlist by default; if a session must call the HQ Worker or OneUp/HeyGen directly, add those hosts to the environment's allowed domains (connectors bypass this, direct fetches do not).
- The Agent SDK bundles the Claude Code binary and requires Node/Python; it cannot run in Cloudflare Workers, and `npm ci --omit=optional` installs it without the binary.
