# 1. OneUp API and account registry

_Research topic: OneUp (oneupapp.io) REST API, MCP server and data export, as the source for an 'all my accounts' registry and later posting/analytics phases_

## Summary

OneUp exposes a simple RESTful JSON API at https://www.oneupapp.io/api/<endpoint>?apiKey=KEY (API key as a query param, generated at oneupapp.io/api-access or the gear icon -> 'API and MCP'), plus a remote MCP server at https://feed.oneupapp.io/mcp/oneup?apiKey=KEY. API/MCP access is included on every paid plan, but Analytics and Comment-management endpoints are gated to Intermediate/Growth/Business. For the account registry the relevant calls are GET /api/listsocialaccounts (every connected account; fields social_account_id, username, full_name, is_expired, social_network_type, account_type), GET /api/listcategory (id, category_name, isPaused) and GET /api/listcategoryaccount?category_id=... (category_id, social_network_id, social_network_name, social_network_type). Posting is POST /api/scheduletextpost | scheduleimagepost | schedulevideopost with category_id, social_network_id (JSON array of ids or "ALL"), scheduled_date_time ("YYYY-MM-DD HH:MM"), content, plus image_url (carousel = URLs joined by ~~~) / video_url, optional title, thumbnail_url, first_comment; GET /api/uploadmedia returns a pre-signed S3 upload_url + file_path for hosting media. Post history is GET /api/getscheduledposts | getpublishedposts | getfailedposts (post_id, content, date_time, social_network_username, category_name), with POST editpost, deletescheduledpost, reschedulefailedpost. There are no webhooks; integrations are Zapier (OneUp is an action app: 'Create Post'), bulk upload from CSV/Google Sheet (max 100 posts, fixed column headers), and downloadable PDF/CSV analytics reports in the UI; no documented CSV export of the account list, so the registry must come from the API. IMPORTANT caveats: the egress proxy blocked docs.oneupapp.io, help.oneupapp.io, www.oneupapp.io and the netlify mirror, so most endpoint details come from search-engine snippets of the docs plus three public GitHub repos whose authors probed the API live in Jul-Aug 2026 (these I read in full). The widely-quoted '3600 calls per 15 minutes' rate limit belongs to developers.oneup.com, a DIFFERENT company (OneUp Sales, London), and must not be assumed for oneupapp.io, whose docs do not surface any rate-limit figure. The MCP server has been reported both working (tool inventory verified live 2026-07-05) and returning JSON-RPC -32603 with a valid key (2026-07-31), so treat REST as the primary path and MCP as optional. Recommended join key between OneUp and the Google Sheet: store OneUp's social_account_id (string) on the sheet row as a durable foreign key, and bootstrap the match with normalized (platform, lowercase handle) from username + social_network_type.

## Facts

- **likely** Base URL is https://www.oneupapp.io/api/ ; the API is a RESTful JSON API; the API key is passed as a query parameter named apiKey on every request: https://www.oneupapp.io/api/ENDPOINT?apiKey=YOUR_API_KEY ([source](https://docs.oneupapp.io/docs/getting-started/authentication/))
- **likely** API key is generated by logging in at https://www.oneupapp.io/api-access and clicking 'Generate API Key'; the key can be revoked/regenerated from the same page. The in-app path is gear icon -> 'API and MCP'. ([source](https://docs.oneupapp.io/docs/getting-started/authentication/))
- **verified** Both oneup-push.mjs (verified live 2026-08-06) and approval-executor.mjs call the API as `${API}/${endpoint}?apiKey=${encodeURIComponent(KEY)}`, with POST bodies sent as application/x-www-form-urlencoded (new URLSearchParams(body)) and GET for list endpoints; GET on scheduletextpost returns HTTP 405 (POST only). ([source](https://github.com/phillipwedgworth-cell/envirocare-website/blob/0484c0d659b263a333fed83d8071643ae4b96f3f/agents/oneup-push.mjs))
- **verified** Response envelope: every call returns { message: 'OK' | <error text>, error: <boolean>, data: [...] }. ## Recommendations

- Registry sync job (Node 22 or a Cloudflare Worker cron): call GET /api/listsocialaccounts, then GET /api/listcategory and GET /api/listcategoryaccount per category; upsert into an `accounts` table keyed by oneup_account_id = social_account_id (store as TEXT, ids are 15+ digit strings). Keep raw_json per row so new fields (profile picture etc.) can be surfaced later without re-syncing.
- Normalize platform on ingest: map social_network_type (string like 'Facebook'/'GBP' or occasionally an int like 13=Reddit) to a canonical enum {tiktok, instagram, youtube, facebook, x, threads, linkedin, pinterest, gbp, snapchat, bluesky, reddit}. Log unknown values instead of dropping rows.
- Join key design: primary = oneup_account_id (social_account_id) written back into a dedicated column of the Google Sheet / registry; bootstrap matching = (canonical platform, lowercase handle without leading '@') from OneUp username vs the sheet's handle column; tie-break on full_name. Show unmatched rows on both sides in the UI for one-click manual linking. Never join on full_name alone (operators rename personas) and never on category (categories are posting groups, not personas).
- Model 'account health' from is_expired (0 ok, 1 needs reconnect) and category isPaused; surface a 'Reconnect in OneUp' badge and a link to https://www.oneupapp.io/login. This is the only health signal the API gives.
- Use OneUp categories as the bridge to avatar kits: one category per avatar persona (or per VA) so listcategoryaccount gives 'which accounts belong to this kit'; store category_id on the kit record. Category names are the only free-text label you control from the API side.
- Posting phase: always send category_id + scheduled_date_time + social_network_id as a JSON-encoded array string + content, as form-encoded POST; schedule at least a few minutes in the future; for video use GET /api/uploadmedia -> PUT to upload_url -> pass file_path as video_url, rather than linking to your own CDN (third-party URLs have been rejected as 'Invalid Image URL').
- Track posts by OneUp post_id from getscheduledposts/getpublishedposts/getfailedposts; poll (no webhooks) on a cron and reconcile by stored post_id only; map 'failed' -> alert + reschedulefailedpost. Pre-schedule >= N days out as the human review window since there is no draft endpoint.
- Keep the API key server-side only (Worker secret / .env); every URL embeds it, so never log request URLs and redact them in error messages (envirocare's helper explicitly does this).
- Treat MCP as optional: wire https://feed.oneupapp.io/mcp/oneup?apiKey=... as a Claude connector for the operator's 'ask Claude' affordance, but build the HQ site on REST; have a feature flag because the MCP server has been observed returning -32603.
- Before building the 'what's working' page, have the operator open https://docs.oneupapp.io/docs/category/analytics (blocked from this session) and paste the Get Analytics Overview / Get Content Analytics request+response examples; also confirm their plan tier (Basic lacks analytics + comments API).
- For the Google Sheet import, start with CSV export -> importer with a column-mapping UI; later use the Sheets API with a service account. Mirror OneUp's own bulk-upload header names (Content, Post Title, First Comment, Image URL, Video URL, Category Name, Social Account Name, Platform, Date Time) so the HQ site can also emit a OneUp-compatible CSV as an escape hatch.

## Gotchas

- Field-name drift across endpoints: listsocialaccounts uses social_account_id / full_name / username; listcategoryaccount uses social_network_id / social_network_name; the posting params use social_network_id; post listings use post_id and social_network_username. Normalize at the client boundary.
- Endpoint is /api/listcategory (singular) and /api/listcategoryaccount — not listcategories / listsocialaccountsbycategory. Guessed names return 404; the real post-management names are getscheduledposts / getpublishedposts / getfailedposts / editpost / deletescheduledpost / reschedulefailedpost.
- social_network_id for posting must be a JSON array encoded as a string (e.g. '["123"]') inside form-encoded params, or the literal string "ALL".
- scheduled_date_time is 'YYYY-MM-DD HH:MM' with no timezone; the timezone is whatever the OneUp account is set to. Confirm the account timezone before scheduling from a server in UTC.
- OneUp may return HTTP 200 with { error: true, message } — check the body, not just the status code. Validation errors fire in parameter order, so a missing field names the next required one.
- social_network_type is usually a string ('Facebook', 'GBP') but has been seen as an integer (13 = Reddit) in list-category-accounts responses.
- The '3600 calls / 15 min' rate limit widely attributed to 'OneUp' is from developers.oneup.com (OneUp Sales, a different company). oneupapp.io's rate limits are undocumented in what we could reach; build with modest polling (e.g. every 5-15 min) and backoff on 429.
- No webhooks and no documented account/queue CSV export: status must be polled, and the registry must come from the API, not a file download.
- Analytics and Comments endpoints are plan-gated (Intermediate+); a Basic plan returns an error, which must be surfaced honestly rather than treated as 'no data'.
- The MCP server (feed.oneupapp.io/mcp/oneup) has been observed both working and returning JSON-RPC -32603 with a valid key within the same month; do not make it the only path.
- Media hosted on third-party URLs has been rejected as 'Invalid Image URL' even when publicly reachable; prefer /api/uploadmedia (pre-signed S3 PUT) and pass the returned file_path.
- Every request URL contains the API key as a query param — redact URLs from logs, error strings and UI toasts; rotate the key at oneupapp.io/api-access if exposed.
- Success responses for scheduletextpost may not include a post_id; have a fallback correlation (scheduled time + account id) and reconcile via getscheduledposts.
- Bulk CSV/Sheet upload caps at 100 posts per upload and Date Time uses 'HH:mm MM/DD/YYYY', a different format from the API's 'YYYY-MM-DD HH:MM'.
- Primary docs hosts (docs.oneupapp.io, help.oneupapp.io, www.oneupapp.io, oneup-docs.netlify.app) were blocked by the egress proxy; endpoint details marked 'likely' were read from search-engine snippets of those pages, not the pages themselves.
